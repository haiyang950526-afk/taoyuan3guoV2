# 名品典籍与密语事件（名品篇）

灵感来源：光荣《三国志》系列名品表（书器文物+所在州县）+ 用户提供的【流民的密语】事件。
本篇做三件事：**① 名品清单与用处设计（含平衡约束）② 获取事件（密语式两步：村民私语→藏匿点调查）③ 未来"名品收集"功能的预留规范**。

引擎事实（已核实）：`equipBonus` 支持饰品位上的 `atk/def/int/spd/luck/crit` 任意组合，所以**典籍做成饰品是纯数据工作，不改引擎**。饰品不支持 HP 加成，本篇不用。

---

## 一、平衡原则（全篇通用）

1. **双轨价值**：每件名品要么"戴着有用"，要么"卖了值钱"，高价品必须 `nosell` 缺省（即可卖）——让玩家自己选"用还是换钱"，这本身就是乐趣。
2. **属性克制**：饰品属性 ≤ 同期商店饰品的 1.5 倍（参照：玉佩 智+3 / 2000 金；诸葛巾 智+20 属顶级彩蛋）。前中期典籍智+3~6，后期 ≤ 智+10。
3. **全部唯一**：每件名品世界仅此一件，获取 flag 一次性。
4. **百分比被动 ≤ 1 件**：像"计策伤害+10%"这种全局被动需要引擎挂钩，全游戏只保留一件（六韬残页），避免滚雪球。
5. **不与情怀名品撞车**：现有 6 件情怀名品（青龙刀等）是"顶级武器"；本篇典籍名器是"智力饰品/收藏品/卖钱货"，定位不重叠。
6. **卖价公式**：卖价 = 标价 50%（现有商店规则），下表"标价"即 items.js 的 price。

### items.js 新增格式（含收集标记预留）

```js
"春秋左氏传": { type: "acc", int: 4, atk: 2, price: 4000, relic: true,
                desc: "名品：关云长夜读之书。智+4 攻+2（唯一）" },
```
**`relic: true` 是预留标记**——当前引擎读到它不生效也无害，将来收集功能按此标记扫描仓库即可（见第四节）。

## 三、获取事件设计（密语式两步）

统一套路：**同一个 NPC 对话两次**——第一次正常寒暄，第二次压低声音塞线索 → 到藏匿点（枯井/老树/草堆）放调查触发器 → 得名品。flag 命名 `wh1`~`wh3`（whisper）。

### 事件 1 · 流民的密语（ch01 · 徐州城）——六韬残页

用户原案，补全为完整两步 + 平衡调整。

**text.js（ch01 下）**：

```js
tanVillager2: ["（那百姓左右张望，忽然压低声音——）",
               "恩公，多谢你们保住了郯城。",
               "实不相瞒……曹军溃逃那晚，我在城西枯井边捡到一个油布包。",
               "我看不懂上头写的啥，藏回井里了。恩公是干大事的人，取去吧。"],
tanVillagerDone: ["（百姓憨笑着摆手）井就在城西，恩公自己去取便是。"],
liuTao: ["（枯井沿上苔痕斑驳。探身一摸——油布包还在。）",
         "（打开，是几页斑驳的竹简抄本，隐约可见'六韬'二字。）",
         "（太公兵法残页。交给军师研读，全军计策必能更进一步。）"],
```

**接线**：`ch01.tanVillager` 所在 NPC 的 branches 按 flag 排序：`wh1` 不存在→原台词+`set:{wh1:"met"}`；`wh1:"met"`→tanVillager2+`set:{wh1:"told"}`；之后→tanVillagerDone。枯井触发器 `if:{flag:"wh1",is:"told"}` → say liuTao + 奖励 + `set:{wh1:"done"}`。

**奖励（两案）**：
- A 案（保留用户原意）：得物品"六韬残页"（`type:"acc", int:3, price:6000, relic:true`）+ 引擎在 `magicDmg` 调用处加一行：`if (S.flags.relic_liutao) dmg = Math.round(dmg*1.1)`。军师计策+10%，全游戏只此一件百分比被动。
- B 案（零引擎改动）：只给饰品（智+3，卖 3000）。

## 四、未来"名品收集"功能的预留规范

现在不改引擎，但约定三件事，将来实现时零返工：

1. **标记**：所有名品在 items.js 带 `relic: true`（本篇清单已全部遵守；现有 6 件情怀名品+七星剑/诸葛巾将来补标即可）。
2. **命名**：物品全名即用典籍/文物本名（"春秋左氏传"而非"春秋残卷"），收集界面直接展示。
3. **判断机制（定稿：得过即算）**：每件名品在**获得动作里顺手 `set: { relic_xxx: true }`**。收集判定、剧情检测、图鉴展示**一律只看 flag，不看背包**——卖掉、存仓库、被剧情收走都算"已收集"。这样名品可以安心做成"可卖高价"，玩家不用在"用钱"和"收藏"之间纠结；05 渡魂记的遗物检测也复用同一套 flag 机制。
4. **图鉴扩展点**：将来在 `engine/ui.js` 的 `showDex()`（宝箱收集段之后）加"—— 名品收集 ——"段：扫描 `ITEMS` 中带 `relic` 的条目，对照 `relic_*` flag 显示 n/N。

**本篇条目互相独立**：典籍做几件、密语事件做几个、黑市货上不上，都可单独取舍。
